# 唤醒延迟 & 屏幕显示文字

> 结论先行：
> 1. 唤醒慢的根因是**用了 MultiNet 自定义唤醒词**（命令词识别），不是 WakeNet 唤醒检测；再加上配了 **4 个别名**。
> 2. 屏幕能显示对话和字幕，**而且服务端代码已经在发文本了**——只是固件编了 emote（猫脸）风格，没地方画字。

---

## 一、唤醒延迟：先定位，再动手

"1 秒才有反应"可能指三个不同的点，优化手段完全不同。用串口日志看时间戳（你已有命令）：

```
py -3.13 -c "import serial,time; s=serial.Serial('COM3',115200,timeout=0.5); s.dtr=False; s.rts=True; time.sleep(0.2); s.rts=False; time.sleep(0.3); print(s.read(20000).decode('utf-8','replace'))"
```

要抓的关键行（按出现顺序）：

| 日志关键字 | 含义 | 这一段耗时说明什么 |
|---|---|---|
| `wake word detected` | MultiNet 判定通过 | 这一段的长度 = **唤醒词识别耗时** |
| `Websocket connected` / `session` | 连上服务器 | 有这一段且耗时明显 → **每次唤醒都在重连** |
| `listen start` | 开始上传音频 | |
| `tts start` | 开始播回答 | |

**三段各自的典型值与对策：**

| 段 | 正常 | 你现在可能的瓶颈 | 对策 |
|---|---|---|---|
| 喊完 → `wake word detected` | 200~400ms | MultiNet 要等词尾静音 + 4 个候选，可能 600~900ms | 砍成 1 个唤醒词；改回 WakeNet |
| detected → `listen start` | 50~150ms | 表情动画渲染、提示音解码 | 关 emote、缩短提示音 |
| listen → 第一句回答 | 1.5~3s | 重连 + ASR + LLM + TTS | 保持长连接（见下） |

## 二、唤醒慢的四个原因（按影响排序）

### 原因 1：MultiNet ≠ WakeNet（最大头）

你的补丁里是：

```
CONFIG_USE_CUSTOM_WAKE_WORD=y
CONFIG_CUSTOM_WAKE_WORD="ni hao xin xin|xin xin tong xue|hai xin xin|ha lou xin xin"
CONFIG_CUSTOM_WAKE_WORD_THRESHOLD=15
```

- **WakeNet** = 专门的唤醒词检测网络，**流式**，词尾一到就出结果，100~200ms。
- **MultiNet** = 命令词识别网络，要**等你把词说完、并检测到一段静音**才敢判定，天然慢一倍以上。
- 而 `duration: 3000`（补丁里 `build_default_assets.py` 的默认值）意味着模型窗口按 3 秒算，判定更保守。

**改法（见效最快）**：

```json
"CONFIG_CUSTOM_WAKE_WORD=\"ni hao xin xin\"",
"CONFIG_CUSTOM_WAKE_WORD_DISPLAY=\"你好心心\"",
```

只留一个词。**4 个候选 → 1 个**，误唤醒率和判定耗时都会降。

> 如果接受换词，最彻底的办法是用 WakeNet 内置中文词（如"你好小智"），一级检测，再快 200~300ms。
> 但孩子叫惯了"心心"，那就保留 MultiNet + 单候选，这是折中最优。

### 原因 2：每次唤醒都可能重连服务器

`.config.yaml` 里 `close_connection_no_voice_time: 120`——120 秒没声音就断。孩子玩一会儿停一会儿，下次唤醒就要**重新握手 + 重新建会话**，这一段在公网/局域网都要 300~800ms。

**改法**：调到 600（10 分钟）甚至更大。代价是服务器上多占一点连接数，单设备无所谓。

```yaml
close_connection_no_voice_time: 600
```

### 原因 3：CPU 没跑满

ESP32-S3 默认可能跑 160MHz。推理（AFE + MultiNet）吃 CPU。

```
# 检查你编译时的 sdkconfig
grep CONFIG_ESP_DEFAULT_CPU_FREQ sdkconfig
# 要看到 CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y
```

没有就加上（`sdkconfig_append` 里写 `CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y`）。**推理快 20~40%**，代价是功耗 +30%（插电设备无所谓）。

### 原因 4：emote 动画在抢 CPU

猫脸表情是 LVGL 在 QSPI 屏上按帧渲染，唤醒瞬间要切表情、加载资源。关掉它（见下一节）能省一点，而且**顺便解决问题 2**。

## 三、屏幕显示文字：改一个 flag 就行

VoCat 板级代码（`main/boards/espressif/esp-vocat/esp_vocat.cc`）：

```c
#if CONFIG_USE_EMOTE_MESSAGE_STYLE
    display_ = new emote::EmoteDisplay(panel, panel_io, DISPLAY_WIDTH, DISPLAY_HEIGHT);
#else
    display_ = new SpiLcdDisplay(panel_io, panel, DISPLAY_WIDTH, DISPLAY_HEIGHT, ...);
#endif
```

| flag | 屏幕长什么样 |
|---|---|
| `CONFIG_USE_EMOTE_MESSAGE_STYLE=y`（你现在） | 猫脸表情，不显示对话文字 |
| `CONFIG_USE_EMOTE_MESSAGE_STYLE=n` | 普通 LCD 界面：**用户说的话 + AI 回答 + 字幕都能显示** |

**关键：服务端已经在发文本了。** 你们的 `plugin/follow_reading.py` 里：

```python
conn.tts.store_tts_text(conn.sentence_id, item.get("text", ""))   # ← 已经是句子原文
```

服务端在 `sendAudioMessage()` 时把这段文本作为 `sentence_start` 的 `text` 发下去，
固件收到后执行 `display->SetChatMessage("assistant", text)`（`application.cc:664`）。

**也就是说：现在播每一句时，屏幕上其实"有字"，只是 emote 界面不画。改 flag 重编一版就能看见。**

## 四、一举两得：编一个 `esp-vocat-text` 配置

在板级 `config.json` 的 `builds` 里加一档（保留原来那档，方便回退）：

```json
{
  "name": "esp-vocat-text",
  "sdkconfig_append": [
    "CONFIG_USE_EMOTE_MESSAGE_STYLE=n",
    "CONFIG_FLASH_EXPRESSION_ASSETS=n",
    "CONFIG_MMAP_FILE_NAME_LENGTH=32",
    "CONFIG_WAKE_WORD_DISABLED=n",
    "CONFIG_USE_ESP_WAKE_WORD=n",
    "CONFIG_USE_AFE_WAKE_WORD=n",
    "CONFIG_USE_CUSTOM_WAKE_WORD=y",
    "CONFIG_CUSTOM_WAKE_WORD=\"ni hao xin xin\"",
    "CONFIG_CUSTOM_WAKE_WORD_DISPLAY=\"你好心心\"",
    "CONFIG_CUSTOM_WAKE_WORD_THRESHOLD=15",
    "CONFIG_SEND_WAKE_WORD_DATA=y",
    "CONFIG_USE_DEVICE_AEC=y",
    "CONFIG_ESP_DEFAULT_CPU_FREQ_MHZ_240=y",
    "CONFIG_SR_MN_CN_MULTINET7_AC_QUANT=y",
    "CONFIG_SR_MN_CN_MULTINET7_QUANT=n",
    "CONFIG_SR_MN_CN_MULTINET6_QUANT=n"
  ]
}
```

编译：`tools/build_firmware_xinxin.bat`（把 board 名换成 `espressif/esp-vocat-text`）。

**刷机只刷 app + assets，别刷整片**（否则 WiFi 凭据被擦）：

```bash
py -3.13 -m esptool --chip esp32s3 -p COM3 -b 460800 write-flash \
   0x20000 build/xiaozhi.bin 0x800000 build/configured_assets.bin
```

## 五、改完能到什么水平

| 项 | 现在 | 改完（估计） |
|---|---|---|
| 喊完 → 屏幕/提示音响应 | ~800~1000ms | **400~600ms**（单候选 + 关 emote） |
| 会话重连 | 每次唤醒可能重连 | 基本不重连（10 分钟保活） |
| 屏幕上能否看到句子 | ❌ 猫脸 | ✅ 对话 + 每句英文字幕 |

> 注意：**回答的第一句不会因此更快**——那 1.5~2 秒是 ASR+LLM+TTS 的固有成本，只能靠"先说一句嗯"或流式输出优化。

## 六、取舍

关掉 emote 的代价是失去表情动画。如果孩子喜欢猫脸眨眼，有两个折中：

| 方案 | 做法 | 工作量 |
|---|---|---|
| 分场景切换 | 平时 emote、进跟读时切 SpiLcdDisplay | 1~2 天（C++） |
| 表情 + 一行字幕 | 改 `EmoteDisplay`，底部加一行文本 | 1 天（C++） |

**建议先做"纯文字版"试三天**，看孩子是更需要字幕还是更需要猫脸——这比自己猜准。
