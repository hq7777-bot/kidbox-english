# 唤醒词可选清单（ESP32-S3 / VoCat）

> 数据来源：`espressif/esp-sr` 的 `Kconfig.projbuild`（87 个 WakeNet 模型，其中 46 个中文）。
> **以你本地实际为准**：在固件目录跑 `python scripts/build.py --list-wake-words` 打印的就是你这份 esp-sr 支持的全集。

---

## 1. 先搞清楚：两个开关不是"两套唤醒词"

| Kconfig | 实际是什么 | 在 VoCat（ESP32-S3）能用吗 |
|---|---|---|
| `USE_AFE_WAKE_WORD` | WakeNet **+ AFE**（降噪/AEC/VAD） | ✅ **能用**，S3 走这条 |
| `USE_ESP_WAKE_WORD` | WakeNet **不带 AFE**（轻量版） | ❌ **不能用**，只给 esp32 / C3 / C5 / C6 |
| `USE_CUSTOM_WAKE_WORD` | **MultiNet**（命令词识别，可自定义任意词） | ✅ 能用，但慢 |

依据（`scripts/build.py`）：

```python
_AFE_WAKE_WORD_TARGETS = {"esp32s3", "esp32p4", "esp32s31"}
_ESP_WAKE_WORD_TARGETS = {"esp32", "esp32c3", "esp32c5", "esp32c6"}
```

**结论：这两个选项用的是同一批 WakeNet 模型，区别只在"音频要不要先过 AFE"。**
而你手上这台 S3 只能用 `USE_AFE_WAKE_WORD`。

唤醒词具体是哪个，由 `CONFIG_SR_WN_*`（选了哪个模型）决定，不是由这两个开关决定。

不指定时，S3 的默认模型是 `wn9_nihaoxiaozhi_tts`（"你好小智"）。

## 3. 针对"心心"的建议

**没有"心心"这个模型，但 `wn9_nihaoxiaoxin_tts`（你好小鑫）发音最接近**
（nǐ hǎo xiǎo xīn vs nǐ hǎo xīn xīn）。

两条路，按代价排序：

| 方案 | 做法 | 延迟 | 孩子要不要改口 |
|---|---|---|---|
| **A. 保留 MultiNet"你好心心"** | 不动，只把 4 个候选砍成 1 个 | 慢（400~900ms） | 不用 |
| **B. 换 WakeNet"你好小鑫"** | `--wake-word wn9_nihaoxiaoxin_tts` | **快（150~250ms）** | 要改成"你好小鑫"，或赌"你好心心"也能触发 |
| C. 换叠词词（小鹿小鹿 / 小龙小龙） | 同上，改模型 ID | 快 | 要改口，但叠词对幼儿更顺口 |

**建议先试 B**：编一版试 10 分钟——如果孩子喊"你好心心"也能触发，那就是白赚 400ms；不能触发再退回 A。

## 4. 怎么切换

```bash
# 1) 看你本地支持哪些（以这个为准）
python scripts/build.py --list-wake-words

# 2) 指定唤醒词编译
python scripts/build.py --board espressif/esp-vocat \
       --wake-word wn9_nihaoxiaoxin_tts

# 3) 刷 app + assets（不刷整片，保住 WiFi 凭据）
py -3.13 -m esptool --chip esp32s3 -p COM3 -b 460800 write-flash \
   0x20000 build/xiaozhi.bin 0x800000 build/configured_assets.bin
```

> ⚠️ 你的板级 `config.json` 里现在写死了 `CONFIG_USE_CUSTOM_WAKE_WORD=y` 等一堆项
> （就是那个 `esp-vocat-xinxin` 档）。要用 WakeNet，**新开一档**别改原档：
> 把 `CONFIG_USE_CUSTOM_WAKE_WORD=n`、`CONFIG_USE_AFE_WAKE_WORD=y`，
> 唤醒词模型由 `--wake-word` 决定（不要再写 `CONFIG_CUSTOM_WAKE_WORD`）。

## 5. 为什么 WakeNet 的唤醒词是固定的，不能自己加

### 5.1 WakeNet 不是"识别器"，是"二分类器"

WakeNet 的输入是一小段音频（约 1 秒），输出只有一个数：**"这段话是不是那个特定词"的概率**。

它**不认字、没有词典、没有音素、没有语言模型**。模型权重里编码的，就是训练时那一个词的声学模式。

> 打个比方：它不是"听写老师"，是"只认一张脸的猫"——换一张脸它就说不认识。

所以"模型"和"唤醒词"是**焊死在一起的**：你换不了词，就像换不了那张脸。

### 5.2 训练一个词要什么

| 需要 | 说明 |
|---|---|
| 数据 | 那个词的真人录音，通常上万条：多说话人、多口音、多距离、多噪声 |
| 流程 | 数据增强 → 训练 → 蒸馏/剪枝 → int8 量化到 100~200KB |
| 工具链 | 乐鑫内部流水线，**不对外发布**（只发训练好的 `.bin`） |

所以"多一个唤醒词"不是加一行配置，而是**再训一个模型**。个人拿不到数据和工具链。

### 5.3 架构上其实支持一个模型带多个词

代码里有 `wakenet_iface_->get_word_num()` / `get_word_name(i)`（`esp_wake_word.cc:120-125`），
官方也确实发布过多词模型，例如 `wn9_hilili_tts` = **"Hi,Lily / Hi,莉莉"** 两个词一个模型。

**结论：能力上能做到，但"你的词"只能在乐鑫训练时写进去，客户端没法追加。**

### 5.4 MultiNet 为什么就能随便加

| | WakeNet | MultiNet |
|---|---|---|
| 干什么 | 判断"是不是这个词" | **音素解码 + 文本匹配** |
| 加词方式 | 重新训练模型 | `esp_mn_commands_add("ni hao xin xin")`，运行时生效 |
| 为什么 | 模型里只有那个词的模板 | 模型输出音素序列，文本→音素是现算的 |
| 代价 | 快（150~250ms）、省电 | 慢（400~900ms）、连续解码更耗 CPU |

### 5.5 想要"自己的词"，现实的三条路

| 路 | 可行性 | 说明 |
|---|---|---|
| **① 近音词 + 调灵敏度** | ✅ **推荐** | 用 `wn9_nihaoxiaoxin_tts`（你好小鑫），并把 `DET_MODE_95` 放宽到 `DET_MODE_90`，"你好心心"有机会触发 |
| ② 换现成词 | ✅ 简单 | 小鹿小鹿 / 喵喵同学 / 你好喵伴，孩子改口 |
| ③ 官方定制训练 | ⚠️ 企业级 | 乐鑫提供定制唤醒词服务，有起订量和费用，个人不划算 |
| ④ 自己训 | ❌ 不现实 | 缺数据、缺工具链、还要做 esp-dl 量化 |

灵敏度那一行在代码里（`main/audio/wake_words/esp_wake_word.cc:47`）：

```cpp
wakenet_data_ = wakenet_iface_->create(model_name, DET_MODE_95);
// DET_MODE_90 更灵敏（更容易触发，误唤醒更多）
// DET_MODE_95 默认
// DET_MODE_99 更严格（误唤醒少，可能叫不应）
```

**这条是"代价换速度"的唯一旋钮**：放宽一档，近音词更容易过；但同时电视里出现"小鑫"也可能唤醒。
