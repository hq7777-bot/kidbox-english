# 双唤醒 + 纯文字界面：实施方案

> 对应需求：
> 1. WakeNet（你好小鑫）+ MultiNet（嗨小鑫 / 小鑫同学 / 哈喽小鑫）**并联**，去重不重复唤醒
> 2. 关掉 emote（猫脸），屏幕显示**纯文字**，并能看出**谁说的**

## 2. 唤醒为什么这样设计

### 2.1 两条路径并联

```
麦克风 → AFE（降噪/AEC）→ 同一份单声道数据
                            ├─▶ WakeNet（你好小鑫）  ~200ms  ─┐
                            └─▶ MultiNet（3 个别名） ~600ms  ─┤
                                                              ▼
                                                    去重窗口 1.2s → 触发唤醒
```

- **WakeNet 命中就立刻返回**，这一轮不再喂 MultiNet——同一句话不会二次触发；
- 即使下一轮 MultiNet 又命中（尾音"同学"还在缓冲里），**1.2 秒去重窗**会把它扔掉；
- `running_` 在触发瞬间置 false，上层 `EnableWakeWordDetection` 重新开启前不会继续检测。

### 2.2 代码里三个关键点

```cpp
// ① 唤醒前先缓存音频（否则 WakeNet 命中时"喊的那句"没进缓存，服务器收不到）
wake_word_audio_cache_.Store(mono_buf.data(), mono_buf.size());

// ② WakeNet 命中 → 立即唤醒并 return
if (r > 0) { TryEmitWake(primary_word_); return; }

// ③ 去重
if (last_wake_us_ != 0 && (now - last_wake_us_) < 1200 * 1000) return;
```

### 2.3 代价（要提前接受）

| 项 | 影响 |
|---|---|
| 内存 | 多一个 WakeNet9 模型（约 100~200KB，吃 PSRAM） |
| CPU | 两套推理并行，约 +15~25%（已同时打开 240MHz） |
| 误唤醒 | WakeNet 这条路径对"你好小鑫"更敏感；MultiNet 阈值 15 仍偏低，若误唤醒多就调到 25 |
| 别名仍慢 | 说"嗨小鑫"依旧走 MultiNet（~600ms）——这是 MultiNet 的固有延迟 |

## 3. 界面为什么这样设计

| 配置 | 效果 |
|---|---|
| `CONFIG_USE_EMOTE_MESSAGE_STYLE=n` | 不再用猫脸 `EmoteDisplay` |
| `CONFIG_USE_WECHAT_MESSAGE_STYLE=y` | 用**气泡聊天**布局：用户消息右对齐+绿色，助手消息左对齐+灰色 |
| `CONFIG_USE_MULTILINE_CHAT_MESSAGE=y` | 长句换行显示，不再横向滚动 |
| `CONFIG_FLASH_EXPRESSION_ASSETS=n` | 不再烧表情资源（省 flash） |

**"谁说的"由气泡左右位置 + 颜色区分**，这是固件里现成的能力（`lcd_display.cc:649-680`），不用自己写判断。

跟读时服务端 `store_tts_text(sentence_id, 句子原文)` → 固件 `SetChatMessage("assistant", 句子)` → 屏幕显示这句英文。**服务端零改动。**

> 如果圆屏上气泡太挤（1.85 寸），可以再关掉 `USE_MULTILINE_CHAT_MESSAGE`，退化成单行滚动。

## 7. 本机复现时补的三个坑（2026-11-09，Windows + ESP-IDF 6.1 实测）

原方案"没编译过"，实际打补丁 + 编译时踩到三处，都已修好并固化：

### 7.1 CRLF：锚点一个都匹配不上

Windows 检出的仓库是 **CRLF**，脚本锚点按 LF 写 → `--check` 直接报"出现 0 次"。
修法：`patch_text`/`patch_feed` 先把文件归一成 LF 再匹配，写回时按原换行恢复。
现在两种换行都能打，同一份脚本可在 Linux 和 Windows 上跑。

### 7.2 WakeNet 模型根本没进 assets（最隐蔽）

`scripts/build_default_assets.py` 里只有这一行决定要不要打包 WakeNet：

```python
if wake_word_config['use_esp_wake_word'] or wake_word_config['use_afe_wake_word']:
    wakenet_model_paths = get_wakenet_model_paths(...)
elif wakenet_model_names:
    print("Note: Found wakenet models ... but wake word type is not ESP/AFE, skipping")
```

我们用的是 **CUSTOM（MultiNet）**，所以 WakeNet 模型被静默跳过 → 固件起来后只会打印
`assets 里没有 WakeNet 模型，退化为纯 MultiNet`，并联等于没做，而且"你好小鑫"根本唤不醒
（它不在 MultiNet 别名表里）。

修法：加一条 `hybrid_wakenet` 判断——`CONFIG_CUSTOM_WAKE_WORD_PRIMARY_DISPLAY` 非空时也打包。
补丁见 `firmware/build_default_assets_hybrid_wakenet.patch`。

**验证方法**（刷机前必做）：
```bash
grep -a "Added wakenet model" build.log        # 应有输出
strings -a build/generated_assets.bin | grep -i nihaoxiaoxin
```

### 7.3 sdkconfig 里同时有小智和小鑫，过滤器会挑错

esp-vocat 板级默认带 `CONFIG_SR_WN_WN9_NIHAOXIAOZHI_TTS=y`（你好小智）。两个都开时
assets 里会有两个模型，`esp_srmodel_filter()` 取**第一个**（按 sdkconfig 顺序 = 小智），
于是并联快路径实际检测的是"你好小智"。
修法：profile 里显式 `CONFIG_SR_WN_WN9_NIHAOXIAOZHI_TTS=n`，只留小鑫。

### 7.4 结论：原方案能编译通过，但"两处逻辑"需要上面 8.2/8.3 才真正生效

| 检查项 | 命令 | 期望 |
|---|---|---|
| 补丁能打 | `apply_hybrid_patch.py --check <repo>` | 5 处全部"检查通过" |
| 模型进包 | `grep "Added wakenet model" build.log` | `wn9_nihaoxiaoxin_tts` |
| 只有小鑫 | `strings generated_assets.bin \| grep -c wn9_nihaoxiaozhi` | `0` |
| 醒的是小鑫 | 串口日志 | `并联 WakeNet 已启用: model=wn9_nihaoxiaoxin_tts word=你好小鑫` |

## 8. 已知风险（诚实说明）

| 风险 | 说明 | 应对 |
|---|---|---|
| **没编译过** | 我这里没有 ESP-IDF 工具链，代码是**对照源码写的**，只验证了"能正确插入、锚点匹配、括号平衡" | 第一次编译大概率有 1~3 处小错，把报错贴回来，我按行改 |
| `FLASH_EXPRESSION_ASSETS=n` | 若 CMake 仍在找表情资源会报错 | 改回 `=y` 即可（只是多占 flash） |
| 圆屏排版 | WeChat 气泡在 360×360 圆屏上可能挤 | 关 `USE_MULTILINE_CHAT_MESSAGE` 或调字号 |
| 双模型内存 | S3 上是 PSRAM 大户 | 若 `create()` 返回 null，日志会提示，功能退化为纯 MultiNet |
| `CONFIG_SR_WN_WN9_NIHAOXIAOXIN_TTS` 符号不存在 | esp-sr 版本不同 | 用 `--list-wake-words` 确认实际模型名，改 profile 里那一行 |
