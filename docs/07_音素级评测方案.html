音素级评测：落地方案

结论：能做，不需要改固件。 难点不在调 API，而在三件事： ① 拿到"孩子读这一句"的录音 ② 音频格式对齐 ③ 分数阈值按孩子校准。

1. 为什么现在做不到（根因）

现在的跟读判定是：

设备录音 → 服务端 ASR（SenseVoice）→ 文本 → difflib 相似度

文字已经丢了发音信息。 孩子把 think 读成 sink，ASR 直接给 sink，或者给 think（因为上下文）， 无论哪种，音素级信息都没了——只能在"音频"上评。

所以要插一个新环节：

设备录音 → [新] 把这句 wav 存下来 → ASR 文本（不变）
                                    ↓
                          [新] 调评测 API（wav + 参考文本）
                                    ↓
                          音素级分数 → 决定通过/重读

2. 第一步：拿到那句录音（关键，已确认可行）

服务端 ASR 基类里已经有现成设施（core/providers/asr/base.py）：

# base.py:268
async def speech_to_text_wrapper(self, pcm_data: List[bytes], session_id: str):
    combined_pcm_data = b"".join(pcm_data)     # ← 这一句的完整 PCM 就在这
    ...
    file_path = self.save_audio_to_file(pcm_data, session_id)  # ← 已有保存函数
    ...
    async def speech_to_text(self, pcm_data, session_id, artifacts)

artifacts 里还带着 pcm_frames / pcm_bytes / temp_path。

做法：不改官方代码，新建一个 ASR provider 继承现有实现，只重写这一个方法：

# 放 data/providers/asr/record_asr.py，在 .config.yaml 里 ASR 选它
import shutil, time
from pathlib import Path
from core.providers.asr.fun_local import ASRProvider as FunASR   # 按实际类名改

REC_DIR = Path("/opt/xiaozhi-esp32-server/data/records")

class ASRProvider(FunASR):
    async def speech_to_text_wrapper(self, pcm_data, session_id):
        # 先落盘，再交给父类做识别（失败也不影响识别）
        try:
            REC_DIR.mkdir(parents=True, exist_ok=True)
            path = self.save_audio_to_file(pcm_data, f"rec_{int(time.time()*1000)}")
            latest = REC_DIR / "last.wav"
            shutil.copyfile(path, latest)
        except Exception as e:
            self.logger.bind(tag="REC").warning(f"保存录音失败: {e}")
        return await super().speech_to_text_wrapper(pcm_data, session_id)

为什么用 last.wav 这个笨办法：跟读是"说完立刻判"，插件拿文本时那句录音就是最近一次——用固定文件名最简单，不用在 conn 上挂属性、不用改框架。并发多个设备时改成按 device_id 命名即可。

工作量：0.5 天｜验收：跟读一句后，data/records/last.wav 出现，能播放，内容就是刚说那句。

若设备是半双工（播放时关麦），孩子跟读的那句照样能录到——因为那时 TTS 已经播完、设备处于聆听态。真正需要全双工的是"录音回放对比"，不是评测。

3. 第二步：选哪家评测 API

方案 音素级 国内可用性 免费额度 备注
Azure 语音 · Pronunciation Assessment ✅ 确定（Granularity=Phoneme） 需国际版账号/信用卡；网络一般可达 F0：5 小时音频/月（≈4500 句） 文档最规范，字段最全（accuracy/fluency/completeness/prosody + 词级 + 音素级）
讯飞语音评测 ISE 🟡 英文音素级通常需开通 en_vip 授权 ✅ 国内注册方便 有试用包 中文最强；英文句子评测好用，音素级要确认授权
腾讯云 SOE 🟡 单词/句子，音素视版本 ✅ 有试用 备选
本地 GOP（wav2vec2 + 强制对齐 + GOP 打分） ✅ 理论可 ✅ 全离线 免费 效果明显不如商业 API，工作量大（1~2 周），不推荐现在做

建议顺序：先用 Azure F0 跑通（音素级是确定的，免费额度够用一年）； 如果注册卡住，再试讯飞 ISE（先用官方 demo 音频验证返回里有没有 phone 字段，再决定投入）。

4. 第三步：调用（Azure REST，最省事，不用装 SDK）

import base64, json, requests

def assess(wav_path: str, ref_text: str, key: str, region: str = "eastasia"):
    cfg = {
        "ReferenceText": ref_text,
        "GradingSystem": "HundredMark",
        "Granularity": "Phoneme",      # ← 关键：音素级
        "EnableMiscue": True,          # 漏读/多读检测
        "PhonemeAlphabet": "IPA",
        "Dimension": "Comprehensive",
    }
    headers = {
        "Ocp-Apim-Subscription-Key": key,
        "Content-Type": "audio/wav; codecs=audio/pcm; samplerate=16000",
        "Pronunciation-Assessment": base64.b64encode(
            json.dumps(cfg).encode("utf-8")).decode("ascii"),
        "Accept": "application/json",
    }
    url = (f"https://{region}.stt.speech.microsoft.com/speech/recognition/"
           f"conversation/cognitiveservices/v1?language=en-US")
    r = requests.post(url, headers=headers, data=open(wav_path, "rb"), timeout=15)
    r.raise_for_status()
    return r.json()["NBest"][0]

音频要求：16kHz / 16bit / 单声道 PCM WAV。 设备是 24kHz Opus，last.wav 如果是 24k，先用 ffmpeg 转一次：

这一步别省。采样率不对，评测分会莫名其妙偏低，很难排查。

5. 第四步：接进跟读流程

改 plugin/follow_reading.py 的判定函数，其他逻辑不动：

def judge(said_text, target_text, wav_path):
    # 1) 优先音素级评测
    try:
        r = assess(wav_path, target_text, KEY)
        total = r["PronunciationAssessment"]["AccuracyScore"]
        bad = [w for w in r["Words"]
               if w["PronunciationAssessment"]["AccuracyScore"] < 60]
        return {"ok": total >= 60, "score": total, "bad_words": bad, "source": "api"}
    except Exception:
        pass
    # 2) 降级：原来的文本相似度（API 挂了也能继续上课）
    from difflib import SequenceMatcher
    s = SequenceMatcher(None, norm(said_text), norm(target_text)).ratio()
    return {"ok": s >= 0.6, "score": s * 100, "bad_words": [], "source": "fallback"}

反馈话术（关键，决定孩子爱不爱用）：

评测结果 说什么
总分 ≥ 80 「很好！」→ 下一句
60~79，某个词低分 「cat 再读一次」→ 重播该句
< 60 「跟着我读：look at the cat」→ 重播 + 慢速版本
连续 2 次不达标 「下一个」→ 跳过（别让孩子卡死在一句上）

音素 → 中文提示（做 15~20 条常用映射就够）：

音素 孩子常错成 提示
/θ/ s / f 「舌尖轻轻放在牙齿中间，别读成 s」
/ð/ z / d 「舌尖轻咬，振动，不是 z」
/r/ l 「舌头卷起来，不要碰牙齿」
/v/ w 「上牙轻咬下唇」
/æ/ e 「嘴张大一点，像说“啊”」

6. 第五步：阈值校准（这步最容易被忽略）

商业 API 的及格线是按成人/考试定的，一年级孩子会普遍偏低，直接用 60 分会让孩子一直"不及格"。

做法：

  1. 先记录孩子的基线：让他读 20 句熟悉的，看平均分（假设 62）；
  2. 把通过线设成 基线 − 5（57），随能力提升每周上调 2 分；
  3. 只对"明显低于基线"的句子提示，不做绝对分数播报（不要念分数给孩子听）；
  4. 分数存进日志，家长周报里看趋势。

10. 附录：v1 判定 vs 音素级（真数字对比）

v1 的判定函数（plugin/follow_reading.py）：

def _score(said, target):
    return difflib.SequenceMatcher(None, _norm(said), _norm(target)).ratio()

_norm 只做小写 + 去标点 + 压空格，所以这是字符级相似度。阈值来自 lesson.json 的 min_score：≤3 词 0.70、≤6 词 0.60、更长 0.50。

实际判定结果（本地跑出来的真实分数）：

目标句 孩子实际（ASR 文本） 分数 阈值 v1 判定 真实情况
Look at the cat. look at the cat 1.00 0.70 通过 完全读对
Look at the cat. look at the sat 0.93 0.70 通过 /k/ 读成 /s/
Look at the cat. look at the cat（ASR 自动纠正） 1.00 0.70 通过 音素错，但被 ASR 洗掉了
Cool birds. cool bird 0.95 0.70 通过 漏了复数 s
Penguins are so cute. penguin are so cute 0.97 0.50 通过 漏了复数 s
I don't like it. like it 0.64 0.50 通过 漏读前半句
Do you like cats? do you like cat 0.97 0.60 通过 漏复数
Look at the cat. I like apples 0.29 0.70 不通过 完全无关

结论：v1 实际只拦得住"胡说八道"。 只要孩子在说英语、词沾边，就会通过。

阈值有多松：Look at the cat 归一化后 15 个字符，阈值 0.70 允许错 4~5 个字符（≈ 一个单词），0.50 允许错 7 个（≈ 半句）。短句反而更松。

两个方向的错判：

  1. 假通过（常见）：ASR 会把发音错误"纠正"成正确单词（语言模型先验），分数直接 1.00。这是结构性盲区，调阈值解决不了。
  2. 假不通过（少见）：人名/生词被 ASR 听错（Ben→Men 还能过，Penguins→Pancakes 就会掉），孩子读对了却被要求重读。
维度 v1（difflib） 音素级评测
判定依据 文本字符相似 音频声学特征
能发现发音错 ❌（ASR 已洗掉） ✅
定位到哪个词 ❌ 只能整句重读 ✅「cat 再读一次」
定位到哪个音 ❌ ✅「/k/ 只拿 30 分」
漏读检测 弱（漏半句 0.64 也过） ✅ miscue 标记
对 ASR 错误鲁棒 差（完全依赖 ASR 文本） 好（不看 ASR，直接评音频）
额外延迟 0 0.6~1.5 s
边际成本 0 免费额度内 0

一句话：v1 回答"有没有跟着念"，音素级回答"念得准不准"。
