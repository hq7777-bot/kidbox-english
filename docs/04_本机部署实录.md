# 本机部署实录（Windows 台式 + ESP-VoCat）

> 记录时间：2026-11-08
> 目标机器：ASUS 台式（i9-13900KF / 64GB / Win10 19045），局域网 IP `192.168.1.10`
> 设备：ESP-VoCat 1.0，MAC `ac:a7:04:e5:f4:fc`，DHCP `192.168.1.16`

---

## 1. 最终可用的架构

```
VoCat（WiFi 2.4G）
   │ OTA: http://192.168.1.10:8003/xiaozhi/ota/
   │ WS : ws://192.168.1.10:8000/xiaozhi/v1/
   ▼
Docker: xiaozhi-esp32-server（G:\xiaozhi-server）
   ├─ ASR  SenseVoiceSmall（本地，中英混合）
   ├─ LLM  DeepSeek deepseek-flash
   ├─ TTS  EdgeTTS zh-CN-XiaoyiNeural
   ├─ 教材 G:\xiaozhi-server\data\lessons（SmartReading 1–6，576 个整篇音频）
   └─ 跟读 G:\xiaozhi-server\data\follow（96 单元 / 1356 句 + lesson.json）
```

Docker 数据目录已搬到 G 盘（`G:\docker-data\wsl`，用目录联接），因为 C 盘只剩 ~6GB。

## 2. 部署过程中踩到的坑（按痛苦程度排序）

### 2.1 WSL 内核太旧 → Docker 起不来
症状：`Error response from daemon: Docker Desktop is unable to start`
解决：开完 WSL2/虚拟机平台功能、重启后，**必须再跑 `wsl --update`**（内核 6.18.40.1 才行）。

### 2.2 Docker 无视 DataFolder，数据仍写 C 盘
`settings-store.json` 里 `DataFolder` 不生效，`docker_data.vhdx` 还在 C 盘。
可靠做法：停 Docker → 复制 `%LOCALAPPDATA%\Docker\wsl` 到 G 盘 → 原路径建 Junction。
停之前必须：`Get-Process *docker* | Stop-Process -Force` + `Stop-Service com.docker.service` + `wsl --shutdown`，
否则报 `Device or resource busy`。

### 2.3 OTA 下发容器内网 IP
默认 OTA 回 `ws://172.18.0.2:8000/...`，设备连不上。必须在 `.config.yaml` 写死
`server.websocket: ws://192.168.1.10:8000/xiaozhi/v1/`。

### 2.4 配网页只吃 JSON
`POST /advanced/submit`、`POST /submit` 用表单编码会报 `Invalid JSON`。
正确姿势：
```
POST /advanced/submit  {"ota_url":"http://…:8003/xiaozhi/ota/","max_tx_power":80,"remember_bssid":true,"sleep_mode":false}
POST /submit           {"ssid":"HUAWEI-315","password":"…"}
GET  /saved/set_default?index=0
再硬复位（esptool --after hard-reset run）才会真正去连
```

### 2.5 `max_tx_power` 填 8 = 2 dBm（最弱）
设备连上就掉线，反复失败后自动回到配网模式。**必须填 80（20 dBm）**。

### 2.6 播报格式改不动（两次踩空）
`play_music` 的播报语和选文件都在 `handle_music_command` / `play_local_music` 内部，
改成返回值没用；而且 `clean_text = re.sub(r"[^\w\s]", "", text)` 会把 `3-3` 削成 `33`，书号直接丢失。
已改为：保留 `.-_/`，播报只返回 `3杠3 U15 课文` 这类标识。

### 2.7 改插件不重启 = 白改
插件是 Python 模块，容器启动时 import 进内存。改文件后必须
`docker restart xiaozhi-esp32-server`，否则跑的还是旧逻辑（现象：代码测试对、真实调用错）。

### 2.8 刷新固件会擦掉 WiFi 凭据
刷整片 `merged-binary.bin`（0x0）会覆盖 NVS。**只刷 app+assets 就不会**：
```
py -3.13 -m esptool --chip esp32s3 -p COM3 -b 460800 write-flash \
   0x20000 build/xiaozhi.bin 0x800000 build/configured_assets.bin
```

### 2.9 edge-tts 7.2.7 被微软 403
`wss://speech.platform.bing.com ... 403 Invalid response status`。升到 7.3.1 即可。
若暂时不能升级，用 `deploy/make_sample_lessons_sapi.py`（Windows SAPI + ffmpeg）离线合成。

## 3. 唤醒词（编译期写死，没有运行时开关）

- 原厂固件模型：`wn9_nihaomiaoban_tts2` → 唤醒词是 **「你好喵伴」**（不是"小智"，喊错就"没反应、只能点屏幕"）
- 当前固件：MultiNet 自定义唤醒词 **你好心心 / 心心同学 / 嗨心心 / 哈喽心心**（阈值 15）+ 设备端 AEC（连续对话）
- 改法见 `patches/xiaozhi-esp32-custom-wakeword.patch`，编译见 `tools/build_firmware_xinxin.bat`
- **注意**：`assets` 分区里存的是唤醒词模型，OTA 只下发 app 分区，所以换唤醒词必须用 USB 刷

---

## 4. 编译固件（Windows，全是坑）

1. 不要用 Docker：Docker Hub / DaoCloud / 1panel 拉 5GB 的 `espressif/idf` 全部失败
2. 官网安装包只到 5.5.6，而项目要求 ≥6.0.1 → 只能源码克隆 `release/v6.1`（SSH 稳定，HTTPS 会被 reset）
3. `install.bat` 和 `idf_tools.py` 都拒绝 MSYS 环境 → 在 PowerShell 里 `Remove-Item Env:MSYSTEM` 后直接调
   `py -3.13 tools/idf_tools.py install --targets=esp32s3`
4. 工具链目录名是 `idf6.1_py3.13_env`，但 `export.bat` 按 PATH 里 python 找 `py3.11_env`
   → 必须 `set IDF_PYTHON_ENV_PATH=...\idf6.1_py3.13_env`
5. `.bat` 必须 **CRLF + ASCII**，LF 换行会让 cmd 整段解析崩溃
6. 板子参数要写 `espressif/esp-vocat`（带厂商前缀），否则报 `board_type not found`

## 5. 服务端 OTA 固件下发（备用）

目录 `data/bin`，命名 `<型号>_<版本>.bin`（如 `esp-vocat_2.6.0.bin`），服务端按型号分组、版本降序下发。
注意：只覆盖 app 分区，不含 assets（唤醒词）。

## 6. 日常运维

```bash
# 看日志
docker logs -f --tail 50 xiaozhi-esp32-server
# 重启（改插件/改配置后必须）
docker restart xiaozhi-esp32-server
# 改 compose（加挂载）后
cd G:\xiaozhi-server && docker compose up -d
# 看设备串口（USB-Serial/JTAG 有完整应用日志）
py -3.13 -c "import serial,time; s=serial.Serial('COM3',115200,timeout=0.5); s.dtr=False; s.rts=True; time.sleep(0.2); s.rts=False; time.sleep(0.3); print(s.read(20000).decode('utf-8','replace'))"
```
