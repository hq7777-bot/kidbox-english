双唤醒 + 纯文字界面：实施方案

对应需求： 1. WakeNet（你好小鑫）+ MultiNet（嗨小鑫 / 小鑫同学 / 哈喽小鑫）并联，去重不重复唤醒 2. 关掉 emote（猫脸），屏幕显示纯文字，并能看出谁说的

1. 改了什么

文件 改动
main/Kconfig.projbuild 新增 CUSTOM_WAKE_WORD_PRIMARY_DISPLAY（并联的 WakeNet 主词，默认"你好小鑫"）
main/audio/wake_words/custom_wake_word.h 加 WakeNet 接口/模型/缓冲区/去重时间戳
main/audio/wake_words/custom_wake_word.cc InitWakenet() + TryEmitWake() + FeedSamples() 重写（同时喂两个模型）
main/boards/espressif/esp-vocat/config.json 新增 build profile esp-vocat-hybrid-text

补丁用脚本打，不手改（脚本会逐条校验锚点，对不上就报错退出，不会写坏文件）：

python <repo>\firmware\apply_hybrid_patch.py --check .    # 先看能不能打
python <repo>\firmware\apply_hybrid_patch.py .            # 真打（每文件留 .bak）

2. 唤醒为什么这样设计

2.1 两条路径并联

麦克风 → AFE（降噪/AEC）→ 同一份单声道数据
                            ├─▶ WakeNet（你好小鑫）  ~200ms  ─┐
                            └─▶ MultiNet（3 个别名） ~600ms  ─┤
                                                              ▼
                                                    去重窗口 1.2s → 触发唤醒
  • WakeNet 命中就立刻返回，这一轮不再喂 MultiNet——同一句话不会二次触发；
  • 即使下一轮 MultiNet 又命中（尾音"同学"还在缓冲里），1.2 秒去重窗会把它扔掉；
  • running_ 在触发瞬间置 false，上层 EnableWakeWordDetection 重新开启前不会继续检测。

2.2 代码里三个关键点

// ① 唤醒前先缓存音频（否则 WakeNet 命中时"喊的那句"没进缓存，服务器收不到）
wake_word_audio_cache_.Store(mono_buf.data(), mono_buf.size());

// ② WakeNet 命中 → 立即唤醒并 return
if (r > 0) { TryEmitWake(primary_word_); return; }

// ③ 去重
if (last_wake_us_ != 0 && (now - last_wake_us_) < 1200 * 1000) return;

2.3 代价（要提前接受）

项 影响
内存 多一个 WakeNet9 模型（约 100~200KB，吃 PSRAM）
CPU 两套推理并行，约 +15~25%（已同时打开 240MHz）
误唤醒 WakeNet 这条路径对"你好小鑫"更敏感；MultiNet 阈值 15 仍偏低，若误唤醒多就调到 25
别名仍慢 说"嗨小鑫"依旧走 MultiNet（~600ms）——这是 MultiNet 的固有延迟

3. 界面为什么这样设计

配置 效果
CONFIG_USE_EMOTE_MESSAGE_STYLE=n 不再用猫脸 EmoteDisplay
CONFIG_USE_WECHAT_MESSAGE_STYLE=y 用气泡聊天布局：用户消息右对齐+绿色，助手消息左对齐+灰色
CONFIG_USE_MULTILINE_CHAT_MESSAGE=y 长句换行显示，不再横向滚动
CONFIG_FLASH_EXPRESSION_ASSETS=n 不再烧表情资源（省 flash）

"谁说的"由气泡左右位置 + 颜色区分，这是固件里现成的能力（lcd_display.cc:649-680），不用自己写判断。

跟读时服务端 store_tts_text(sentence_id, 句子原文) → 固件 SetChatMessage("assistant", 句子) → 屏幕显示这句英文。服务端零改动。

如果圆屏上气泡太挤（1.85 寸），可以再关掉 USE_MULTILINE_CHAT_MESSAGE，退化成单行滚动。

4. 编译与烧录

5. 验收

5.1 串口日志（开机应出现）

I (xxx) CustomWakeWord: 并联 WakeNet 已启用: model=wn9_nihaoxiaoxin_tts word=你好小鑫 chunk=512

如果看到：

日志 含义 处理
assets 里没有 WakeNet 模型 编译时没带上 wn9 模型 确认 profile 里有 CONFIG_SR_WN_WN9_NIHAOXIAOXIN_TTS=y
拿不到 WakeNet 接口 esp-sr 版本没有这个模型 换 --list-wake-words 里有的词
退化为纯 MultiNet 同上 功能仍可用，只是没有快路径

5.2 行为验收

# 操作 期望
1 说"你好小鑫" ≤300ms 有反应（屏幕切换/提示音）
2 说"嗨小鑫""小鑫同学""哈喽小鑫" 能唤醒，但明显慢一点（~600ms）
3 连续说"你好小鑫"两次（间隔 <1s） 只唤醒一次
4 说完"你好小鑫同学"（连读） 只唤醒一次
5 唤醒对话 屏幕：你说的话在右（绿），小鑫的话在左（灰）
6 跟读一句 屏幕显示这句英文

7. 已知风险（诚实说明）

风险 说明 应对
没编译过 我这里没有 ESP-IDF 工具链，代码是对照源码写的，只验证了"能正确插入、锚点匹配、括号平衡" 第一次编译大概率有 1~3 处小错，把报错贴回来，我按行改
FLASH_EXPRESSION_ASSETS=n 若 CMake 仍在找表情资源会报错 改回 =y 即可（只是多占 flash）
圆屏排版 WeChat 气泡在 360×360 圆屏上可能挤 关 USE_MULTILINE_CHAT_MESSAGE 或调字号
双模型内存 S3 上是 PSRAM 大户 若 create() 返回 null，日志会提示，功能退化为纯 MultiNet
CONFIG_SR_WN_WN9_NIHAOXIAOXIN_TTS 符号不存在 esp-sr 版本不同 用 --list-wake-words 确认实际模型名，改 profile 里那一行
